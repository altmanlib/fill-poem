# 用户流程与页面状态机

## 1. 目标与范围

定义活动「竹林雅集 · 国宝寻金」移动端 H5 的页面、跳转与状态，作为交互、视觉与实现的共同依据。产品输入见 [创意方案摘要](../briefs/2026-10-08-01-panda-coin-h5-brief.md)，页面画面见 `preview-1022/` 设计稿。

范围：从两个入口进入，到集章、合成、新品介绍、抽奖、留资的完整路径。

不在本文展开：题库定稿、奖品与概率、埋点字段。

## 2. 现状与约束

| 项 | 说明 |
|---|---|
| 载体 | 移动端 H5，单页应用 |
| 仓库形态 | Monorepo：`fill-poem-web`（Vite）+ `fill-poem-api`（Go） |
| 设备 | 竖屏手机为主；设计稿宽 750（2x of 375） |
| 网络 | Loading 需覆盖首屏资源就绪；弱网可重试 |
| 入口 | ① 官方渠道发布；② 用户分享链接 |

## 3. 原则

1. **单向主路径**：集章按关卡顺序前进，不提供跨关跳转入口
2. **通关单一路径**：没有失败终态；答错只触发提示与降难度，直到答对
3. **规则先于作答**：同一次页面会话内，规则页至少完整展示一次
4. **抽奖可重复进入**：集齐金章后，首页入口直达抽奖页，不重玩关卡

## 4. 方案

### 4.1 主路径

```text
入口① / 入口②
  → Loading
  → 首页
  → 规则页（会话内至少一次）
  → 填字闯关 第 1~4 关（每关通关弹窗）
  → 合成页
  → 新品介绍页
  → 抽奖页
       ├─ 未中奖：弹窗，留在抽奖页
       └─ 中奖：弹窗 → 留资页 → 保存后回抽奖页
```

首页另有「获奖信息」入口，直达留资页，用于事后回填。抽奖页有「返回主页」。分享引导见 §4.6。

### 4.2 页面职责

| 页面 | 职责 | 离开条件 |
|---|---|---|
| Loading | 加载必要资源，展示进度 | 资源就绪（失败可重试） |
| 首页 | 主 KV、标题、「即刻出发」、「获奖信息」 | 点击其中之一 |
| 规则页 | 4 条玩法规则、「开始游戏」 | 点击开始 |
| 填字闯关 | 展示诗句、候选字、「提交」；判定对错 | 第 N 关通关并确认弹窗 |
| 通关弹窗 | 恭喜文案，引导下一关；第 4 关按钮为「前往见证」 | 点击按钮 |
| 答错弹窗 | 见 §4.4 | 点击「我再试试」 |
| 合成页 | 四枚金章汇聚合成熊猫金币；「前往品鉴」 | 点击按钮 |
| 新品介绍页 | 2027 版熊猫贵金属纪念币信息；「抽首发好礼」 | 点击按钮 |
| 抽奖页 | 剩余抽奖次数、「抽奖1次」、分享入口、「返回主页」 | 抽奖结果 / 返回 |
| 抽奖结果弹窗 | 未中奖「好的」；中奖「填写获奖信息」 | 点击按钮 |
| 留资页 | 姓名、电话、地址表单与说明；「保存信息」 | 保存成功后回抽奖页 |

### 4.3 关卡

| 关 | 名称 | 填字数 |
|---|---|---|
| 1 | 初入雅集 | 1 |
| 2 | 品句寻韵 | 2 |
| 3 | 观藏识珍 | 3 |
| 4 | 金章将现 | 4 |

- 填入方式：点击或拖拽候选字填入空缺；点已填空缺可退回
- 候选字含迷惑项；每关通关得一枚国宝金章，共 4 枚
- 题库配置在 `fill-poem-web/src/game/stages.ts`，诗句以设计稿为准，终稿待甲方确认
- 第 4 关通关后进入合成页；集齐金章的用户再次点「即刻出发」直达抽奖页

### 4.4 答错规则

| 次数 | 表现 |
|---|---|
| 首次答错 | 弹窗「字词似乎不合雅韵，不妨再斟酌一番」，已填内容清空，可重试 |
| 第二次及以后 | 弹窗「诗意相助，为你扫清迷雾！」，系统排除混淆项，只保留正确字 |

### 4.5 抽奖次数

| 来源 | 次数 |
|---|---|
| 首次集齐四枚金章 | 3 |
| 首次分享活动 | 额外 1 |

次数扣减、中奖判定与中奖记录必须由服务端记账，前端只展示结果。身份依据待定（见 §9 O1）。

### 4.6 分享

入口②为用户分享链接落地。抽奖页提示「点击右上方，首次分享可获1次抽奖机会」。分享引导页的画面与渠道待定（见 §9 O2）。

### 4.7 留资

- 字段：姓名、电话、地址；电话按 11 位手机号校验
- 仅中奖记录的持有者可进入；可重复进入修改，以最终提交为准
- 提交时间段为活动上线期间，具体日期待定
- 个人信息的存储与导出范围随隐私告知文案一并确定

### 4.8 状态

前端状态：当前关卡序号、已得金章数、剩余抽奖次数；规则页已展示标记存于会话存储。系统返回键由路由层接管：规则页、抽奖页、留资页返回首页，其余页面忽略返回。

## 5. 影响面

| 面 | 影响 |
|---|---|
| 前端路由 / 视图 | 8 个路由（loading / home / rules / stage / combine / intro / lottery / lead），弹窗为页面内层 |
| 后端 | 抽奖次数账本、抽奖服务、留资、名单导出 |
| 资源加载 | Loading 需定义就绪清单（字体、首屏图、关卡配置） |
| 文案与视觉 | 各页素材按设计稿切图，规划见 ROADMAP R023、R029 |

## 6. 测试或验证策略

| 用例 | 预期 |
|---|---|
| 冷启动 | 先见 Loading，就绪后到首页 |
| 主路径走通 | 首页 → 规则 → 4 关 → 合成 → 新品介绍 → 抽奖 → 留资 |
| 答错两级 | 首次答错可重试；第二次起候选字只剩正确字 |
| 会话内重进 | 规则页已展示后，首页直接进入闯关；集齐金章后直达抽奖页 |
| 抽奖次数 | 次数为 0 时按钮不可用；并发与幂等由服务端测试覆盖 |
| 返回手势 | 系统返回不破坏进度 |

## 7. 迁移与兼容

无历史线上版本。`prototype/v260929-1` 仅作格子交互参考。

## 8. 明确不做

- 不做多玩家实时对战
- 不在首页之前插入广告或外链打断
- 不提供后台管理界面，名单仅导出
