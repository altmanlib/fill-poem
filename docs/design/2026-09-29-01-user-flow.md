# 用户流程与页面状态机

## 1. 目标与范围

定义「填字组诗」移动端 H5 的主路径页面与跳转关系，作为后续交互、视觉与实现的共同依据。

范围：从进入页面到分享海报 / 再来一次的完整用户路径。

不在本文展开：题库内容、计分细则、海报视觉稿、埋点字段。

## 2. 现状与约束

| 项 | 说明 |
|---|---|
| 载体 | 移动端 H5，单页应用 |
| 仓库形态 | Monorepo：`fill-poem-web`（Vite）+ `fill-poem-api`（Go） |
| 已有参考 | `prototype/v260929-1/index.html`（开始 → 答题 → 结算） |
| 设备 | 竖屏手机为主；宽度按常见机型适配 |
| 网络 | Loading 需覆盖首屏资源就绪；弱网可重试 |

## 3. 原则

1. **单向主路径**：正常游玩沿主路径前进，不提供跨阶段乱跳入口
2. **结果二分**：通关成功进入分享；失败进入重试，不混在同一结果语义里
3. **规则先于作答**：进入填字前必须经过规则介绍
4. **可重开**：失败与成功后均可回到可再玩状态，不要求刷新浏览器

## 4. 方案

### 4.1 主路径总览

```text
Loading
  → Home
  → 交互动画
  → 规则介绍
  → 填字组诗
  → Result
       ├─ 成功：展示结果 + 生成分享海报
       └─ 失败：展示失败 + 再来一次
```

### 4.2 阶段说明

| 阶段 | 职责 | 进入条件 | 离开条件 |
|---|---|---|---|
| Loading | 加载必要资源，展示等待态 | 打开页面 | 资源就绪（或失败可重试） |
| Home | 活动入口 / 主题呈现 | Loading 完成 | 用户触发进入 |
| 交互动画 | 引导性互动与氛围铺垫 | 离开 Home | 动画/互动完成，或用户跳过（若提供） |
| 规则介绍 | 说明玩法与操作方式 | 交互动画结束 | 用户确认开始 |
| 填字组诗 | 核心答题 | 规则确认 | 判定成功或失败 |
| Result · 成功 | 展示通关结果，生成并提供分享海报 | 答题判定成功 | 分享完成 / 再玩 / 离开 |
| Result · 失败 | 展示失败信息，提供再来一次 | 答题判定失败 | 再来一次 / 离开 |

### 4.3 状态机

```text
                     ┌──────────┐
                     │ Loading  │
                     └────┬─────┘
                          │ ready
                     ┌────▼─────┐
                     │   Home   │
                     └────┬─────┘
                          │ enter
                     ┌────▼─────┐
                     │ 交互动画  │
                     └────┬─────┘
                          │ done
                     ┌────▼─────┐
                     │ 规则介绍  │
                     └────┬─────┘
                          │ start
                     ┌────▼─────┐
              ┌──────┤ 填字组诗  ├──────┐
              │      └──────────┘      │
              │ success                │ fail
       ┌──────▼──────┐          ┌──────▼──────┐
       │ Result成功   │          │ Result失败   │
       │ + 分享海报   │          │ + 再来一次   │
       └──────┬──────┘          └──────┬──────┘
              │                        │
              │         retry          │
              └───────────┬────────────┘
                          │
                          ▼
                     （回到可再玩节点，见 §4.4）
```

### 4.4 再来一次的落点

| 场景 | 落点 | 理由 |
|---|---|---|
| Result 失败 → 再来一次 | 默认回到「规则介绍」；若用户本局已看过规则，可直达「填字组诗」 | 降低重复阅读成本，同时保证首次必经规则 |
| Result 成功 → 再玩 | 同上 | 成功与失败共用重开语义，减少分叉 |

具体是否「跳过规则」由实现时用会话内标记控制；本文默认：**同一次页面会话内，规则介绍至少完整展示一次**。

### 4.5 Result 两种形态

| 形态 | 必有内容 | 主操作 |
|---|---|---|
| 成功 | 通关展示文案 / 视觉；可生成的分享海报 | 分享海报；可选再玩 |
| 失败 | 失败说明；不生成海报 | 再来一次 |

成功态以「生成分享海报」为闭环动作；失败态不以分享为主路径。

### 4.6 与原型的关系

`prototype/v260929-1` 将开始、答题、结算压成三屏，且结算始终出「前世文豪」，无明确失败分支。

本流程在原型之上拆出 Loading / Home / 交互动画 / 规则介绍，并将 Result 明确为成功 / 失败二分。原型仅作视觉与答题交互参考，不作为页面结构最终稿。

## 5. 影响面

| 面 | 影响 |
|---|---|
| 前端路由/视图 | 至少 6 个阶段视图（Result 可视为同一视图两种状态） |
| 资源加载 | Loading 需定义就绪清单（字体、首屏图、题库等） |
| 海报 | 仅成功路径需要 canvas / 图片导出能力 |
| 文案与视觉 | Home、交互动画、规则、成败 Result 均需独立素材规划 |

## 6. 测试或验证策略

| 用例 | 预期 |
|---|---|
| 冷启动 | 先见 Loading，就绪后到 Home，不可跳过到答题 |
| 主路径走通 | Home → 动画 → 规则 → 答题 → 成功 Result，可触发生成海报 |
| 失败路径 | 答题失败 → 失败 Result → 再来一次可再次进入答题 |
| 会话内重开 | 同会话第二次进入时，规则可按 §4.4 跳过或保留 |
| 返回手势 | 系统返回不破坏状态机；若无法拦截，至少不丢关键进度约定（见开放项） |

## 7. 迁移与兼容

无历史线上版本。从原型迁到本流程时，答题格子交互可复用，页面骨架按本状态机重建。

## 8. 明确不做

- 不做多玩家实时对战
- 不做账号体系与服务端存档（除非后续单独立项）
- 失败路径不生成分享海报
- 不在 Home 之前插入广告或外链打断

## 9. 开放项

| 编号 | 问题 | 影响 |
|---|---|---|
| O1 | 「交互动画」的具体形式与是否允许跳过 | Home 之后的时长与实现量 |
| O2 | 成功 / 失败的判定规则（正确题数、超时、步数等） | 填字组诗与 Result 的边界 |
| O3 | 再来一次默认落点：规则介绍 vs 直接答题 | §4.4 的最终取值 |
| O4 | 系统返回键 / 手势是否允许回退到上一阶段 | 路由实现方式 |
| O5 | 分享海报的渠道（系统分享 / 长按存图 / 微信 JSSDK 等） | 成功 Result 的技术选型 |
| O6 | Loading 失败与超时的重试文案、最长短等待 | Loading 态完整性 |

## 10. 落地顺序

1. 按本状态机搭空视图骨架与切换
2. 接入填字组诗核心玩法（可参考原型）
3. 补齐规则介绍与成败 Result
4. 实现成功态海报生成
5. 再定稿交互动画（依赖 O1）
